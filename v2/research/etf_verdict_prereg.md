# ETF 판정 — 보유 비중 가중 카드 판정 합산 · 사전 등록 (2026-10-19, 규칙 버전 etf-v1)

**구현: `v2/etf/etf_daily.py`(설정 `v2/etf/ticker_alias.json`, 서명 `v2/etf/verdict_code_sig.js`, 대체 `v2/etf/etf_fallback.py`).**

## 왜, 무엇을
- 투자 원칙 4(10-19): "카드 있는 개별 종목과 ETF를 산다." ETF에는 10-Q·DCF가 없어, 사용자 결정으로 **보유 비중 가중으로 기존 카드 판정을 합산**한다.
- 역할(사용자 결정): **참고용 · 매수 기준 아님.** 원칙 1(초저평가~적정만 매수)은 개별 종목 조항이라 ETF에 적용하지 않고, ETF 매수 규칙은 Portfolio 원칙에서 따로 정한다.
  이 문서는 원칙 4의 "지수 ETF 규칙"이 아니다(QQQ 대조 제외는 그대로). 예측 신호로 검증되지 않았다.
- 첫 ETF: SPY 한 장. 홈 "시장 지표" 구역의 칩·요약 줄과 ETF 카드 페이지(preview 전용). 둘째 ETF: QQQ(2026-10-21, 아래 "입력 형식 B"). 셋째: DIA(2026-10-21, 다우존스 산업평균 30종목 — SPY와 같은 운용사·입력 형식 A, 판정은 설정만 추가).
- QQQ 판정도 참고용이다. Portfolio 원칙 4의 "QQQ는 지수 ETF 규칙을 정할 때까지 원칙 대조에서 뺀다"는 그대로 — 이 판정을 원칙 대조에 쓰지 않는다.

## 규칙
1. **입력 검사.** 머리 줄(Ticker·Weight·Identifier, Name은 있으면 쓴다)과 "Holdings: As of D-Mon-YYYY"(일은 한두 자리) 줄이 있어야 한다. 데이터 줄 = 머리 줄 뒤 첫 빈 줄까지(그 뒤는 면책 문구).
   데이터 줄의 Weight가 하나라도 비었거나·수가 아니거나·음수이거나, 같은 Identifier(빈 값·"-" 제외)가 두 줄 이상이거나, 데이터 줄이 없거나, 분모 D가 0이면 → ETF "판정 보류"(입력 오류).
   입력 오류만 바로 멈추고, 아래 다른 보류 조건은 모두 모아 규칙 9 순서로 대표 하나를 고른다(나머지도 reasons에 기록).
2. **줄 분류**(위에서부터 첫 해당 하나): (가) 비주식 — 설정 `nonEquity`의 Identifier(현금 US DOLLAR, TPG CVR) (나) 매핑 — 회사 키(설정 `company`로
   바꾼 티커, 없으면 티커 그대로)가 카드 이름과 같음 (다) 카드 없음 — 티커가 영대문자·점 모양이고 Identifier가 있음 (라) 분류 안 됨 — 나머지.
3. **분모.** D = (가)를 뺀 모든 줄의 Weight 합, w = Weight ÷ D. (다)(라)는 D 안에 남아 덮지 못한 비중이 된다. (라)가 D의 0.5%를 넘으면 보류(분류 안 됨).
   모든 비교는 반올림 전 값.
4. **회사 단위.** 같은 회사 키로 가는 줄은 비중을 더한다(GOOGL+GOOG, FOXA+FOX, NWSA+NWS). 표시도 회사 단위.
5. **카드 서명.** 매핑된 카드마다 (a) 판정 코드 해시(dcfLevel·bankLevel·rimLevel + "종합 평가 자동 판정" IIFE, 티커 접두어 제거, sha256 앞 12자)가
   설정 `approvedVerdictCode`에 있어야 하고(추출 성공 여부와 상관없이 매핑된 카드 전부 — 추출이 실패한 카드도 해시는 따로 잰다) (b) judges가 정확히 3개 [자기 이력, 동종업, 현금흐름|초과이익], 가중치 [1, 1, 2], 표 값 자기 이력·동종업 ∈ {−1, 0, +1, 기권},
   셋째 ∈ {+1, 0, −1, −2, 기권}이어야 한다. 하나라도 어긋나면 **ETF 전체** 보류(카드 판정 코드 변경 — 승인 필요 / 카드 판정 구조 변경).
   해시 (a)는 표 값 사전(DV)·문턱(30·70)·합산식이 IIFE 안에 있어, 오늘 아무 카드도 새 분기를 타지 않는 변경까지 잡는다. 추출기 자체의 변경은 잡지 않는다(입력 해시로 기록만).
   10-16 승인 해시 4종: DCF 카드 117장, 은행 RIM 11장, 건강보험 RIM(ELV·UNH) 2장, BRKB 1장. 카드 판정 코드를 바꾸면 ETF는 사람이 새 해시를 확인해 승인할 때까지 보류된다(의도한 마찰).
   카드별 보조 검사: 같은 judges로 카드 규칙 판정을 다시 내서 카드 판정과 다르면 그 카드만 제외(규칙 불일치). 추출 오류·날짜 없음도 그 카드만 제외(추출 오류).
6. **카드 점수.** n = 4 × Σ(앉은 표) ÷ Σ(앉은 가중치)(카드 JS와 같은 식, 기권이 있으면 4/3 단위). 범위 [−4, +3]. 앉은 심판이 없으면 n = 없음.
   "판정 보류" 카드는 n을 비공개 계산에만 기록하고 c·n̄에 넣지 않는다(공개 산출물의 카드별 n은 판정에 쓴 카드만 — 보류 카드는 +4가 나올 수 있다).
7. **날짜.** 기본(dateRule `same`): S(보유 파일 As of)가 P와 같아야 한다(아니면 ETF 전체 보류: 보유 파일 날짜). 카드 판정 날짜(카드 일봉 마지막 날)도 P와 같아야 쓴다(아니면 그 카드 제외: 날짜 불일치).
   받기 실패면 이전 파일을 쓰지 않는다(보유 파일 받기 실패). 받은 시각·실행 시각·S·P를 기록한다.
   **사전 고정한 대안 B**(dateRule `prev_ok`): S ∈ {P, P의 직전 거래 세션}, 카드 날짜 = P. 직전 거래 세션은 NVDA 카드 일봉 날짜를 달력으로 쓴다.
   고르는 조건: 매일 실행 시각에 S가 P의 직전 세션으로 밀려 있는 관측이 거래 세션 5개 중 4개 이상(받기 실패한 날은 세지 않는다). 다른 대안은 고르지 않는다.
8. **판정.** c = 판정에 쓴 비중 합. c < 0.70이면 보류. 아니면 n̄ = Σ w·n ÷ c, 카드 문턱(≥3 저평가 · ≥1 적정~저평가 · >−1 적정 · >−3 적정~고평가 · 나머지 고평가).
   어느 문턱과 0.25 안이면 "경계 근처"(표시만).
9. **보류 사유.** 위 규칙으로 보류가 정해졌을 때의 대표 사유 하나(나머지도 기록). 우선순위: ETF 스크립트 실행 실패(대체 단계 또는 예상 밖 예외) > 보유 파일 받기 실패 > 자체 검사 불일치 >
   입력 오류 > 보유 파일 날짜 > 카드 판정 추출기 실패(추출기·서명 스크립트가 통째로 실패) > 카드 판정 코드 변경 > 카드 판정 구조 변경 > 분류 안 됨 > (c < 0.70일 때) 카드 추출 오류 또는 카드 날짜 불일치(그 비중이 D의 30% 이상이면 큰 쪽) > 덮은 비중 부족.
   홈의 "묵음"(builtFor ≠ 홈 priceSession), "불러오지 못함"(데이터 파일 없음·문법 오류), "형식 오류"(값의 모양이 어긋남)는 화면이 붙이는 상태다.
   추출기·서명 스크립트가 통째로 실패하면(node 없음·시간 초과·비정상 종료·깨진 출력) 그때까지 모은 조건과 함께 멈추고, 대표는 모은 것 중 우선순위가 가장 높은 것이다.
   서명을 아예 못 잰 카드(서명 스크립트가 그 카드에서 실패)도 "카드 판정 코드 변경"으로 보류하되 상세에 "서명을 못 잰 카드 — 카드 파일 확인"으로 구분한다.
   보류 상세에는 운용사 Identifier·비중 값을 넣지 않는다(행 번호·티커·개수만) — 공개 산출물과 Actions 로그에 실린다. 예상 밖 예외는 종류 이름만 공개하고 전체 추적은 비공개 폴더에. 보류면 판정 자리에 "판정 보류 · 사유", n̄·범위는 대시.
10. **범위**(표시만): lo = c·n̄ + (1−c)·(−4), hi = c·n̄ + (1−c)·(+3). 1−c에는 카드 없음·판정 보류·제외·분류 안 됨이 모두 든다.
11. **카드 한 장의 제외 사유**가 여럿이면 추출 오류 > 규칙 불일치 > 날짜 불일치 > 판정 보류 순서의 첫 것이 막대 칸을 정한다(판정 보류 → "판정 보류", 나머지 → "그 밖 제외").
    막대 = 5등급 + 카드 없음 + 판정 보류 + 그 밖 제외 + 분류 안 됨 = D 기준 100%.
12. **자체 검사.** Σw = 1, 막대 합 = 1, 0 ≤ c ≤ 1, 쓴 비중 합 = c, 쓴 n ∈ [−4, +3], lo ≤ n̄ ≤ hi, ok면 c ≥ 0.70, 그리고 세 산출물(<ETF>.json·카드 페이지 data-etf·홈 데이터)의
    상태·사유·판정·n̄·c·범위·막대·S·builtFor·규칙 버전이 같아야 한다(막대 불변식은 보류여도 막대가 계산됐으면 본다). 어긋나면 셋을 "자체 검사 불일치" 보류로 다시 쓰고, 다시 쓴 셋도 대조한다.

7a. **갱신 대기**(2026-10-20 변경 기록의 내용을 번호로 — 기존 번호는 그대로). 모은 보류 사유가 "보유 파일 날짜" 하나뿐이면 직전 정상 판정을
   날짜 꼬리표와 함께 유지한다(S < P면 직전 판정이 P 직전 세션 또는 P 세션 것일 때, S > P면 P 세션 것일 때, 한 세션까지, 그 사이 ruleVersion·
   dateRule·분류표·판정 추출기가 바뀌었으면 보류). ETF마다 따로(관측 date_obs.jsonl의 etf 칸). 대안 B(prev_ok) 관측도 ETF마다 새로 센다.

## 입력 형식 B — Invesco 보유 JSON(QQQ, 2026-10-21, 설계 dr 3라운드 합의)
규칙 3~12는 형식 A(SSGA xlsx, SPY)와 같다. 규칙 1·2만 아래로 바꿔 읽는다. 규칙 버전은 etf-v1 그대로, 산출물에 `inputFormat`("invesco_json")을 둔다.
- 입력: `https://dng-api.invesco.com/cache/v1/accounts/en_US/shareclasses/46090E103/holdings/fund?idType=cusip&productType=ETF`.
  Invesco 이용약관도 복제·재게시를 제한한다(개인 비상업적 사용) — SPY와 같은 공개 수준(원본·줄 단위 비중은 올리지 않고 상위 10개·막대·원본 sha256만, 사용자 결정 10-21).
  로컬 스크립트는 406으로 막히고 Actions(ubuntu)에서는 받힌다(10-21 시험).
- **B-1 입력 검사.** JSON 문법이 아니면 보유 파일 받기 실패. 문법은 맞는데 최상위가 객체가 아니거나, `effectiveDate`(= S)가 실제 날짜(YYYY-MM-DD)가 아니거나,
  `holdings`가 빈 배열·배열 아님이거나, 줄이 객체가 아니거나 securityTypeCode가 문자열이 아니면 입력 오류.
  비중 `percentageOfTotalNetAssets`: 비주식 줄만 null 또는 유한 음수 허용. 그 밖 모든 줄(주식·모르는 종류)은 유한한 0 이상 수(bool·문자열 아님) — 아니면 입력 오류.
  ticker·cusip은 문자열 또는 null(다른 자료형은 입력 오류). 같은 cusip(빈 값 제외)을 비주식 밖 줄끼리 또는 주식·비주식 사이에 쓰면 입력 오류 — 비주식 줄끼리는 허용(지수선물과 그 합성현금이 NQZ6를 나눠 쓴다). D = 0이면 입력 오류.
- **B-2 줄 분류 순서.** (가) 비주식: securityTypeCode ∈ 설정 nonEquityTypes(IFUT 지수선물·CURR 통화·CURRCOL 통화담보·SYN 합성현금, 10-20 실측) →
  모르는 종류: equityTypes(COM·ADR·DRNY, 10-20 실측) 밖 → 분류 안 됨 / 주식인데 ticker 또는 cusip이 빔 → 분류 안 됨 → (나) 회사 매핑(설정 company 또는 ticker = 카드 이름) →
  (다) 카드 없음(영대문자·점 티커) → (라) 분류 안 됨. **D = (가)를 뺀 모든 줄의 비중 합**(분류 안 된 비중 포함). 선물·합성현금을 빼는 근거는
  판정 범위가 "주식 보유"이기 때문(파생상품 노출은 평가하지 않는다).
- 날짜·갱신 대기·서명·합산·판정·보류 순서·자체 검사는 형식 A와 같다. 보수율: SEC 485BPOS 2025-12-19(accession 0001104659-25-123273) Total Annual Fund Operating Expenses 0.18%.
- 10-20 첫 계산(구현 확인, 참고): S = P = 2026-10-20, 106줄(비주식 5), 회사 100, 맞은 카드 45장 중 44장 사용(판정 보류 1). c = 82.60%, n̄ = −2.019 → 적정~고평가.

## 산출물 대조 단계(2026-10-21)
카드 생성기(`v2/index/index_daily.py --card <ETF>`)가 판정 페이지를 ETF 카드로 덮어쓴 뒤, 커밋 전에 `v2/etf/etf_consistency.py`가 ETF마다 세 산출물
(<ETF>.json · 홈 데이터 칸 · 최종 페이지의 data-etf)의 규칙 12 칸을 대조한다. 어긋나면 그 ETF만 "자체 검사 불일치" 보류 하나로 다시 쓰고 다시 대조,
그래도 어긋나면 그 실행은 커밋·게시하지 않는다(다음 실행이 다시 평가). 알림(etf_alerts.py)은 모든 ETF·대조 뒤 한 번 — 카드 판정 코드 해시는 ETF 공통이라
code_sig 이슈도 하나로 모은다(모든 ETF가 이번 실행에서 ok일 때만 닫는다). 산출물의 runId가 이번 실행이 아니면 알림은 그 ETF를 "검사 못 함"으로 본다.

## 실패 처리
- `etf_daily.py`는 받기·형식·계산을 하나의 try로 감싸 어디서 실패하든 세 산출물을 보류로 쓰고 종료 코드 0. 파일은 임시 파일 뒤 교체(파일별 원자적).
- 워크플로 ETF 단계는 continue-on-error. 단계가 실패하면(스크립트가 아예 못 돈 경우) `etf_fallback.py`(표준 라이브러리만)가 세 산출물을 "ETF 스크립트 실행 실패"로 쓴다.
- 홈은 builtFor ≠ priceSession이면 묵음, 데이터가 없거나 깨지면 "불러오지 못함"으로 그린다. ETF 파일은 Python 게시 단계(build_index·validate)가 읽지 않으므로 종목 게시를 막지 못한다.
- 종목 쪽 게시가 실패하는 날은 홈 전체가 게시되지 않고 기존처럼 워크플로 실패 메일이 온다 — ETF가 따로 보장하지 않는다.

## 알려진 한계
(가) 카드 척도가 [−4, +3]로 비대칭이라(가치 함정 때문에 "매우 싸다"도 +1) 평균은 아래로 기운다 — 원칙 1을 ETF에 그대로 쓰면 SPY는 사실상 늘 매수 불가가 되고,
Portfolio의 ETF 매수 규칙이 이 단어를 쓰면 편향을 물려받는다(그 규칙 문서에도 옮길 것). n̄의 역사적 기준선은 없다.
(나) 평균은 극단을 지운다(절반 +3·절반 −4면 "적정") — 막대를 함께 보인다.
(다) 상위 10개 회사가 판정에 쓴 비중의 절반쯤이다(10-16: 51.3%).
(라) 덮지 못한 비중은 지수의 작은 쪽이라 n̄은 카드가 있는 대형주 평균에 가깝다(방향은 모른다, 운용사 파일의 섹터 칸이 비어 섹터 대조도 못 한다).
(마) c = 0.70에서 범위 너비 2.1점 > 판정 밴드 너비 2점 — 문턱 근처에선 범위가 늘 두 단어에 걸친다.
(바) NVDA(10-16 7.86%)처럼 큰 카드 한 장이 보류되면 c가 70% 아래로 떨어져(77.73 − 7.86 = 69.87) SPY와 무관한 이유로 보류된다.
(사) 판정 보류는 지금 보험·복합 금융(현금흐름 계산 불가: BRKB·PGR·CB)에 몰린다.
(아) 원본을 공개하지 않으므로 지난 날의 n̄를 공개 자료만으로 다시 계산할 수 없다 — 공개 SPY.json의 카드별 n·판정·상위 10개 비중과 원본 해시까지만 남는다.
(자) 운용사 파일 합계가 100.22%인 이유는 확인하지 못했다(10-16). 모든 줄에 같은 배율이면 정규화로 지워지지만 특정 줄의 중복·묵은 값이면 아니다 — 같은 Identifier 중복은 규칙 1이 잡는다.
(차) DIA는 30종목이라 큰 카드 한 장의 보류가 c를 크게 움직인다(10-20 상위 GS 비중이 약 10% — 그 카드가 보류되면 c가 87%대에서 77%대로). 70% 문턱은 그대로.
    DJIA는 주가 가중이지만 판정은 DIA 보유 파일의 비중을 그대로 쓴다(주가를 다시 곱하지 않는다).
