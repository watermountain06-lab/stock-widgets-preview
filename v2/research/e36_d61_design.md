## 1. E36 — 최신 분기를 더 새 후보 태그에서(정의 확인 뒤)
`extract_concept`는 (연간 이력 있음, 최신 결산일) 순위로 태그 A를 골라 연간·최신 분기를 모두 A에서 가져온다. 바꾸는 것 — **대상 키는 분기 점수에 쓰이는 손익 항목만**: revenue·costOfRevenue·operatingIncome·pretaxIncome·netIncome·netIncomeAttributableToParent·interestExpense·epsBasic·epsDiluted. 재무상태표 항목, 현금흐름(operatingCashFlow·capex — XBRL이 누계로 내는 관행이라 3개월 비교가 맞지 않음)·배당은 대상 아님(지금 규칙 그대로):
1. **후보 목록** = `CONCEPTS_BY_CIK` 적용 뒤의 목록(회사별로 좁힌 목록에 일반 CONCEPTS 태그를 끼우지 않음).
2. **회사별 지정 먼저**: 그 CIK·키가 `LATEST_Q_BY_CIK`에 있으면 일반 규칙을 **적용하지 않는다**(지금 코드대로 지정 태그로 최신 분기 교체, 바꾸면 `latestQuarterTag` 기록).
3. **사실 정리(재현성)**: 태그마다 단위 `USD`(주당 값 키는 `USD/shares`)만, 같은 (start, end)는 `filed`가 가장 늦은 것 하나(같으면 `accn` 사전순 마지막), 3개월 = 80~100일.
4. **A의 최신 3개월 분기** qA(10-Q, 3개월만 — A의 최신 10-Q가 누계뿐이면 그 앞의 3개월 값). 후보 B마다 최신 3개월 분기 qB(10-Q). qB.end > qA.end인 후보를 결산일 늦은 순(같으면 목록 앞)으로 하나씩 본다.
5. **정의 확인**: A와 B가 **같은 (start, end)** 로 둘 다 값을 낸 기간(3개월·누계·연간 어느 길이든, 비교 열 포함)을 모두 모아 — 2개 이상이고, 그중 0이 아닌 값이 하나 이상 있고(0만 겹치면 정의 확인이 안 됨), **모두** |B − A| ≤ 2% × max(|A|, |B|)(둘 다 0이면 같음)이면 그 B의 qB를 최신 분기로 쓰고 `latestQuarterTag = B`. 아니면 다음 후보. 모두 실패하면 A 그대로 + 경고 `quarter_tag_mismatch: A→B(이유)`.
6. 2% 일치는 "자동으로 바꿔도 되는 수치 기준"일 뿐 정의가 같다는 증명이 아니다 — 경고가 난 곳은 사람이 원문을 보고 `LATEST_Q_BY_CIK`나 `CONCEPTS_BY_CIK`로 정한다.
7. B의 최신이 누계뿐이면(3개월 값 없음 — CBOE 설비투자) 후보에서 빠지고 경고 `quarter_tag_ytd_only`.

## 2. D61 — 순이자 기준 표기
`build_fundamental_score.score_items` 이자보상배율에서 **실제로 쓴 값의 출처**를 먼저 정한다: ① 그 분기 태그 값(`latestQuarterTag` 있으면 그것, 없으면 `tag`; 연간 기준이면 `tag`) ② 태그 값이 없어 `interest_extra.json` 손입력 `value`를 쓴 경우 그 항목. `adjust`는 출처를 바꾸지 않는다. **부호**: 계산은 "비용 크기(양수)"로 먼저 바꾼 뒤 조정한다 — 총이자비용 태그·손입력은 절댓값(음수 부호로 공시했으면 표기), 순이자 태그는 −값(비용이 음수로 실리므로) — 아래 처리 순서의 b와 같다. `adjust`는 언제나 비용 크기 기준(양수 = 비용을 늘림, 지금 WMT 항목과 같은 뜻)으로 더한다.
- 출처가 순이자 태그 {`InterestIncomeExpenseNonoperatingNet`, `InterestIncomeExpenseNet`}이거나 손입력 항목에 `net: true`면 순이자 기준이다. 손입력 순이자 항목(desc가 "순이자"·"Interest expense, net"·이자수익 차감인 것) PM·MO·IEX·DAL·DG·CDW·ZBRA·TMUS에 `net: true`를 더한다(NEM "net of capitalized interest"·RTX·NOW는 총이자라 제외).
- 처리 순서: 영업이익 ≤ 0 → 지금처럼 1점(영업적자) 먼저. 그다음 **최종 비용 값 c**를 한 번 만든다: 원시 값 v(태그 값 또는 손입력 value) → 비용 크기 b(총이자 태그·손입력은 |v| — v < 0이면 회사가 비용을 음수 부호로 공시한 것(DIS 10-K)이라 `note: "음수 부호로 공시(절댓값)"`; 순이자 태그는 −v) → c = b + Σadjust. 이후 판정과 계산은 모두 c 하나로 한다 — **c > 0**: 배율 = 영업이익 ÷ c(순이자 기준이면 `note: "순이자 기준"`); **c = 0**: 총이자 기준이면 지금처럼 "이자비용 0" 5점, 순이자 기준이면 결측 `"순이자 0(이자비용 미공시)"`; **c < 0**(순이자가 수익): 결측 `"순이자 수익(이자비용 미공시)"`(총이자 기준은 b ≥ 0이므로 c < 0은 조정이 비용보다 큰 자료 이상 — 결측 + 경고. DIS 10-K `InterestExpense` FY2021~2025 −1,546M~−2,070M은 b 단계에서 절댓값이 돼 지금 코드 `op / abs(iv)`와 같은 점수). 예: 순이자 v −100, adjust +50 → b 100, c 150 → 영업이익 300이면 2.0배. 원시 값으로 나누지 않는다. 순이자 태그에서 수익·비용 판정은 b가 아니라 c로 한다.
- 지금 순이자 카드 8장(EMR·FCX·GWW·HWM·LOW·MCO·TRGP·WM)은 최신 분기가 모두 비용(음수)이라 점수 변화 없음, 표기만 생김. 손입력 8장(PM·MO·IEX·DAL·DG·CDW·ZBRA·TMUS)도 표기만.

## 3. 검증
1. 시험(가짜 facts): 바꿈(겹침 2개 이상·모두 2% 안), 겹침 1개 → 경고, 한 기간이라도 2% 넘음 → 다음 후보 → 모두 실패 경고, 겹침 없음 → 경고, B 누계뿐 → 경고, A 최신 10-Q가 누계 → 그 앞 3개월로 qA, 같은 (start, end) 정정 공시 → 늦은 filed, 경계(정확히 2%, 2% 초과, 양쪽 0, 반대 부호), LATEST_Q_BY_CIK 키는 일반 규칙 건너뜀, CONCEPTS_BY_CIK 좁힌 목록 유지. 실물 1-1 표와 같은 결과.
2. D61: 순이자 비용·0·수익, 영업적자 우선, 손입력 net, 연간 기준, adjust — 순이자 −100 + adjust +50 → b 100·c 150(부호 시험), 순이자 +20 + adjust +50 → c 30 → 배율(부호 뒤집힘), 총이자 −1,812(DIS 연간형) → b 1,812로 지금과 같은 점수, 총이자 −100 + adjust +50 → b 100·c 150(조정 방향 유지). **결합 시험**: E36이 분기만 B(순이자 태그)로 바꾼 fixture에서 분기 기준은 B 출처로 "순이자 기준"·부호, 연간 기준은 A 출처로 표기 없음.
3. 변이: 겹침 2개 조건 제거(겹침이 정확히 1개이고 2% 안인 fixture가 바뀜), "모두"를 "최근 하나"로(DELL·FCX가 바뀜), 0이 아닌 겹침 조건 제거(0만 겹치는 fixture가 바뀜), LATEST_Q 우선 제거, 순이자 0 → 5점 복원, 비용 크기 변환 제거(부호 시험) → 시험 빨강.
