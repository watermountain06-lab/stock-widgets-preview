# B17 한계 매출/자본 · 운전자본 — 사전 등록 (2026-10-03, 돌리기 전에 고정)

안건 B17(`after_100_cards_agenda.md`). 2026-10-03 DCF 검증(Codex·Fable)에서 나온 두 문제를 다룬다. 결과를 본 뒤 이 문서를 고치지 않는다.
바꿀 일이 생기면 "변경 기록"에 날짜·이유와 함께 덧붙인다.

## 문제
- **운전자본(버그)**: `base_inputs`의 운전자본은 유동부채에서 `LongTermDebtCurrent`만 되돌린다. 기업어음·단기차입·유동 금융리스가 늘면
  운전자본이 줄어 순투자가 작게 잡힌다. 두 시점 중 한쪽 운전자본이 비면 `(nwc or 0)`이라 변화분이 운전자본 전체가 된다.
- **한계 매출/자본(추정 잡음)**: `marginal_s2c`는 최근 1년 매출 증가 ÷ 1년 순투자다. 순투자가 작은 해에 상한 10까지 튄다
  (PG 10 대 평균 1.10 → 기본 > 낙관 > 보수, 평균만 쓰면 기본 −4%).

## 비교하는 변형 (엔진 파일은 그대로 두고 메모리에서 계산)
- **V0 지금.**
- **V1 운전자본 수정**: 되돌릴 단기 차입 = max(`DebtCurrent`, 유동 장기차입(`LongTermDebtAndCapitalLeaseObligationsCurrent`가 있으면 그것,
  없으면 `LongTermDebtCurrent`) + `ShortTermBorrowings`(없으면 `CommercialPaper`)) + `FinanceLeaseLiabilityCurrent`(유동 장기차입에
  금융리스 포함 태그를 쓴 경우는 빼고). 두 시점 중 한쪽 운전자본이 없으면 운전자본 변화 = 0. 1년 한계 그대로.
- **V2**: V1 + 최근 2년 누적(2년 매출 증가 ÷ 2년 순투자 합 + 2년 운전자본 변화).
- **V3**: V1 + 최근 3년 누적.
- **V4**: V1 + 1년 한계를 평균 비율의 0.5~2배 안으로 제한.
- 상한 10·하한(순투자·매출 증가 ≤ 0이면 정의 안 함 → 평균)은 모든 변형에 같다.

## 고르는 표본과 지표 — 카드가 아니라 S&P500 비금융 전체
- 유니버스: `verdict_replay.py`와 같은 S&P500 통제 유니버스(금융·제외 4종목 빼고), 자료는 `.facts_20261002`·`.prices10y`.
- 평가일: 분기 말 월의 마지막 거래일 2025-06·2025-09·2025-12·2026-03·2026-06·2026-09(6개). 모든 입력은 그때 공시분만.
- 지표:
  ① **흔들림** — 같은 종목의 연속 분기 |ln(한계 비율_t ÷ 한계 비율_{t−1})|의 전 종목 중앙값(둘 다 정의된 쌍).
  ② **상한 비율** — 상한 10(V4는 2×평균 포함)에 걸린 관측 비율.
  ③ **정의 안 됨 비율** — None(평균으로 떨어짐) 관측 비율.
  ④ **순서 뒤집힘**(마지막 평가일, 참고) — 기본 시나리오 > 낙관 시나리오인 종목 비율.

## 판정 규칙 (결과 보기 전 고정)
1. V1은 버그 수정이라 **무조건 채택 후보**에 넣는다(지표와 무관).
2. V2·V3·V4 중 흔들림 ①이 V1보다 **상대 10% 이상** 낮고, ③이 V1 + 5%p 이하, ②가 V1 이하인 변형만 후보.
   후보가 여럿이면 ①이 가장 낮은 것, 차이가 상대 10% 안이면 단순한 쪽(V4 → V2 → V3 순).
3. 후보가 없으면 **V1만** 적용한다.
4. 카드 100장 적용은 **영향 보고용**이다(판정·기본값 변화 목록). 고르는 데 쓰지 않는다. 판정이 바뀌는 카드가 있으면 사용자가 정한다.
5. 채택 전 Codex(코드·재현성)·Fable(비판) 검토, 최종 결정은 사용자.

## 하지 않는 것
- 수익률 IC 검정. 이것은 추정 잡음을 줄이는 측정 문제이고, 순위 정보 검정(A0)과 별개다. IC로 고르면 18개월 단일 국면에 맞춘 선택이 된다.
- `EquitySecuritiesFvNi` 전액 차감은 이번에 바꾸지 않는다(두 시점에 같은 값이면 변화분에서 지워진다). 결과에 영향 종목만 적는다.

## 변경 기록
- 2026-10-03 (결과 확인 후, 구현 수정 — 사용자 승인) 첫 실행의 V1 구현이 새 단기 차입을 같은 결산일 값만 써서, 분기 보고서에 단기 차입 태그가 없는 회사(MCD 등 — 연말에만 공시)는 새 값이 0이 되고 엔진의 옛 값(latest)과 기준이 달랐다(Fable 발견, MCD 0.78 → 2.07이 착시). 구성요소는 결산일 값이 없으면 결산일 이전 200일 안의 마지막 값(엔진 신선도 기준)으로 바꾸고, `DebtCurrent`를 쓸 때는 금융리스를 더하지 않는다(이미 포함, TSLA). 연속 분기끼리만 짝짓고, 판정은 반올림 전 값으로(Codex). **판정 규칙·지표는 그대로.**
  수정 전 결과: 흔들림 V0 0.390 · V1 0.341 · V2 0.247 · V3 0.204 · V4 0.140, 정의 안 됨 45~47%, 상한 V1 5.5% · V2 5.2% · V3 6.0% · V4 16.1% → V2.
- 2026-10-03 (결과 확인 후, 보조 지표 추가 — 사용자 승인, 판정에 쓰지 않음) Fable 지적: 연속 분기 흔들림은 창이 겹치는 변형(2·3년)에 유리하다. 4분기 간격 흔들림과, 각 변형(및 평균 비율)이 다음 해 실제 1년 한계 비율을 얼마나 맞히는지(중앙 |ln 오차|)를 함께 보고한다. 둘이 등록 지표와 엇갈리면 그 사실을 적고 사용자가 정한다.
- 2026-10-03 (결과 확인 후, 엔진 이식 때 구현 수정 — Fable 2차) 태그 우선순위: 결산일에서 이어 쓴 옛 값이 같은 결산일 값을 이기지 않게, **결산일이 더 최근인 후보가 먼저**, 같으면 큰 쪽(VZ 2025-12 이어 쓴 $18.6B 대 2026-06 $21.8B, CVS·DG·KMB·MAR·YUM 같은 모양). 사전 점검 숫자에는 이 결함이 남아 있다 — 엔진(`build_dcf.current_debt`)에만 반영.
- 2026-10-03 **사용자 결정: 등록 규칙의 V2 대신 V1 채택.** 이유: V2의 우위는 창이 겹치는 연속 분기 지표에서만 나왔다(4분기 간격 −9.6%로 10% 미달), 다음 해 실제 1년 비율을 평균보다 못 맞혔다(평균 0.800 · V2 0.828 · V4 0.624), V2 카드 변화 26장은 대부분 "평균으로 떨어짐" 전환이다(ADI·SNDK). XOM 판정 변화(기업어음 $0 → $3.06B가 운전자본으로 잡혀 한계 비율 상한)는 규칙대로 두고 카드에 이유를 적는다.
