# 카드 항목별 갱신 확인 목록 (v2)

2026-09-23, 완성된 v2/NVDA 카드(2026-09-22 종가 $228.87)의 화면 값을 전부 뽑은 표다.
70장 변환(1단계)의 기준 문서이고, 3단계 파이프라인이 그대로 구현할 명세다.

"확인하는 법"은 "어제와 달라졌다"가 아니라 **오늘 종가로 독립 재계산한 값과 일치하는가**다.
밸류에이션 탭이 "뭔가 바뀌었으니" 통과했던 것이 이 칸이 없었던 결과다.

범례: **P** = 종가 · **Q** = 분기 공시 · **H** = 사람 판단 · ⚙ = **스크립트화 필요**(값을 만드는 코드 없이 손으로 박힌 값)

변수 이름은 NVDA 기준이다. 다른 카드에서는 `NVDA_`를 `{T}_`로 읽는다.

## 3단계(파이프라인 이식)에서 처리할 과제

NVDA 화면은 완성본이다. 아래는 화면을 바꾸자는 것이 아니라, 파이프라인이 이 값들을
갱신하려면 필요한 배관이다. 1단계 변환에서는 NVDA 틀을 그대로 따른다.

1. **코드가 없는 값** — 적정주가 밴드, 현재가, 등락률, 밸류에이션 탭 제목. 스크립트를 붙이지 않으면 갱신할 수 없다.
2. **같은 숫자의 출처가 둘 이상** — `MULTIPLE_DATA` 자기 막대와 `NVDA_VALUATION`, FCF 칸과 `FUND_COMPARE`, 네 곳의 다음 실적일.
3. **동종업 점수 기준일** — NVDA는 2026-08-27/09-11로 카드 주가(09-22)보다 오래됐다. "같은 날" 규칙을 매일 지키려면 피어 배수 갱신이 필요하다.
4. **HTML 대체값의 세대 차** — 헤더 요구 성장 대체값 "연 25.4%" vs JS 26.2%. 화면은 맞지만 JS가 죽으면 옛 숫자가 보인다.

## 변환하면서 정한 규칙 (AAPL, 2026-09-24)

틀(NVDA)에 되돌려 반영할 것은 **[틀]**로 표시한다. NVDA 화면은 지금 숫자로는 영향이 없다.

- **종합 평가** — 사람 판단. AAPL "고평가"(자기 이력 12.5 비싸다 · 내재가치 −60% 비싸다 · 동종업 48.0 중간).
- **할인율** — 70종목 비교 전까지 10% 고정(backlog "DCF 할인율"). Codex는 CAPM-WACC, Fable은 10% 유지 + 참고 표시.
- **비영업 투자자산에 `MarketableSecuritiesNoncurrent` 추가** (`build_dcf.py`). AAPL 장기 채권 $84.1B가 주주가치에서 빠져 있었다(기본 $125.64 → $134.03). 200일 넘게 낡은 계열은 버린다. NVDA 불변 확인.
- **순현금 = 현금 + 단기투자 + 장기 채권 − 차입금 − 리스.** 지분증권은 제외(`build_fundamental_score.net_cash`). AAPL −$2.44 → +$3.32.
- **자본배분은 현금흐름표 지급액 기준**(NVDA $19.7B·$6.0B와 같은 기준). 자본변동표의 발생 기준(AAPL $25.9B)과 섞지 않는다. 잔여 매입 한도는 공시가 없으면 칸을 뺀다.
- **이자보상배율 결측** — v1 규칙대로 0점, 칸에 "이자비용을 따로 공시하지 않아 계산할 수 없다"를 적는다.
- **[틀] 안정성 종합 진단은 규칙** — 재무건전성 축 비율에 v1 등급 단어(80 우수·60 양호·40 보통·미흡), 색 30/70. 해설 문단은 10-Q 대차대조표 사실로 쓴다.
- **[틀] 활동성 색은 DSO+DIO 규칙 유지**, CCC가 음수면 문장을 "판매 대금을 받고도 N일 동안 공급업체 돈으로 운영하는 구조"로 바꾼다. CCC 막대 눈금은 max(영업순환주기, 지급기간), 음수 구간도 그린다.
- **[틀] 금액 뒤 조사를 숫자에 기대지 않는다** — "지금 가격($X)이", "기본 시나리오($Y)를".
- **[틀] 브랜드 색 리터럴 치환** — `rgba(118,185,0,…)`·`#76b900`·`#9fdb2f`(NVDA 초록)이 차트·버튼·CCC 막대에 박혀 있다. 복제 때 종목 강조색으로 바꾼다.
- **체크포인트·산문은 1차 출처로 다시 쓴다.** 루트 카드에서 옮긴 AAPL 문장 중 CEO 승계 "9월 예정"(이미 9/1 취임)과 관세 $3.3B(출처 없음, 콜은 관세 환급 효과 +1%p)가 틀렸다.
- **적정주가 밴드 산식 검증** — NVDA로 $260~$370이 재현됨(최근 252거래일 시점별 TTM EPS로 나눈 PER의 p25·p75 × 현재 TTM EPS, $10 반올림). AAPL $300~$330.
- **직접 바꿔보기 자는 로그 눈금 유지** — 선형 눈금(점 사이 거리 = 달러 간격)을 AAPL에 시험했다가 사용자 결정으로 되돌렸다(2026-09-24). 로그 눈금에서는 할인율을 바꿔도 시나리오 사이 거리가 거의 그대로인데, 비율이 일정해서 생기는 정상 동작이다.
- **[틀] 점수 구성표(`.score-comp`) 칸은 한 줄 유지** — 900px 이하에서 한 칸이 아래 줄로 접혔다. `.sc-tiles` 줄바꿈 금지, `.sc-group`은 `flex:1 1 0; min-width:max-content`(넓을 땐 같은 폭, 좁으면) 폭이 모자라면 그룹이 통째로 다음 줄로. 520px 이하는 칸 44px·이름 9px. 390px에서 확인.
- **피어 비교 차트 값은 손 상수**(스크립트로 계산했지만 매일 갱신 안 됨) — 3단계 파이프라인 과제. 같은 날 종가·분모 직접 계산. 축 밖 값(AMZN PCR 367x)은 `excluded` + 툴팁에 실제 값.
- **[틀] 배수 위치 배지** — 백분위 50% 이상이면 "5년 중 상위 N%". 이력이 1200거래일 미만이면 이름 옆에 "최근 N년 이력"(NVDA 손값 "2024.08~ 이력" 대체).
- **[틀] 요약 격자(`.logic-grid`) 4칸 한 줄 기준 1100px → 980px** — 1100px 창에서도 2×2였다. 4칸은 박스 약 220px까지 한 줄로 버틴다(1000px 확인, 900px에서 내재가치 칸이 접힘).
- **헤더 밴드 적중 칸 (NVDA·AAPL 반영 완료)** — 라벨 "밴드 적중률 (맞은 날/센 날일, 쏠림)", 값은 비율. 쏠림은 이탈이 한쪽뿐이면 "이탈 전부 하단/상단", 양쪽이면 많은 쪽 "하단우세/상단우세". NVDA 58.3% (407/698일, 이탈 전부 하단), AAPL 75.9% (540/711일, 상단우세). 목표 80%·상하단 일수는 툴팁(2026-09-24 사용자 결정). 색은 비율 30/70. 확인: 종가가 밴드 경계 안인 날을 직접 센다.

1. **복제** — `python3 v2/clone_card.py {T}`. 이름·머리·브랜드 색(초록 리터럴 포함)을 루트 카드에서 읽어 치환한다. 남은 NVDA 흔적 목록을 출력한다.
2. **배열** — DAILY·MA5/20/60/120·BACKTEST를 루트 카드에서 스크립트로 잘라 붙인다. 길이 동일, `MA20[-1]` = 최근 20일 평균 확인. 손으로 옮기지 않는다.
3. **데이터 블록** — CIK가 `v2/build_activity_score.py` CIKS에 없으면 추가. 재무 파일을 redesign에서 `v2/fundamental_data/`로 복사. 순서: `fetch_eps_history` → `build_multiple_history --json v2/{T}_multiples.json` → `build_peer_score --self … --card` → `build_fundamental_score --card` → `build_activity_score` → `build_dcf`(scenarios·implied_growth로 `{T}_DCF` 작성) → `build_dcf_grid` → `build_dcf_track`.
4. **헤더 손값** — 현재가·등락·기준일, "실제 3년 +N%"(`history()['growth_3y']`), 적정주가 밴드(252거래일 시점별 PER p25~p75 × TTM EPS, $10 반올림), 종합 평가(사람 판단, 먼저 "확인 필요"로).
5. **판단 콘텐츠** — 루트 카드에서 옮기되 **문장마다 1차 출처로 다시 확인**. AAPL에서 루트 카드의 CEO 승계 "예정"(이미 끝남)·관세 $3.3B(출처 없음)가 틀렸다. 자사주 매입은 현금흐름표 기준인지 확인.
6. **틀 전용 문장 제거** — NVDA 산문(반도체 시장 규모, 56.6% 마진, 회사채 발행 등)이 그대로 남지 않았는지 `grep -i nvda`와 탭별 읽기로 확인.
7. **대체값 맞추기** — 탭을 다 채운 뒤 `python3 v2/sync_fallbacks.py {T}`(서버 필요). JS가 그린 값을 HTML 대체값에 되써 넣는다. 적용 전후 렌더 글자가 같은지 비교한다. 탭을 열 때만 채워지는 칸(`fundPeriodTitle`)은 손으로. AAPL 43곳·NVDA 13곳이 낡아 있었다(Codex).
8. **확인** — `node --check`는 문법만 본다. **다섯 탭을 실제로 열어 콘솔 에러 0건과 차트 4개(분기 실적·YoY/QoQ·매출 구성·비교)가 그려지는지** 확인한다(MSFT에서 `const revenue`의 공백이 치환으로 빠져 `constrevenue=`가 됐는데 문법 검사는 통과하고 분기 차트만 비었다). 그 밖에 `node --check`(인라인 JS), `python3 -m http.server`로 띄워 콘솔 0건. **주소에 `?v=N`을 붙여 캐시를 피한다**(수정한 NVDA가 캐시 때문에 옛 화면으로 보였다). 창 폭 1100·900·700·390에서 요약 격자·점수 구성표·헤더 네 칸 높이.
9. **탭마다 사용자 확인** — 표시 형식(라벨/값에 무엇을 둘지) 요청은 구현 전에 "라벨: … / 값: …"으로 한 줄 되물어 맞춘다.
- **[틀·반영됨] 애널리스트 등급은 `{T}_ANALYST.rating`** — "Strong Buy"가 HTML에 박혀 있었다(AAPL은 Buy). 목표가 여력이 음수면 빨강(`op-down`) — `op-up` 초록이 고정돼 AAPL −2.6%도 초록이었다.

## 내재가치 모델 교체 — 매출/자본(sales-to-capital) (2026-09-24, 사용자 결정)

- **왜** — 옛 모델은 EBITDA 마진을 고정하고 감가상각만 설비투자를 따라 올려, 투자 비용은 물리고 투자 성과는 0이었다(AMZN "현재 마진 유지" 시나리오의 영업이익률 12.1% → 7~10%, MSFT 46.8% → 38~43%, 카드 문구와 계산 불일치). 영업이익률만 고정하는 중간안은 반대로 상각이 늘수록 현금이 남고 4~5년차 순투자가 음수가 되어(Fable 지적·재계산 확인) 버렸다.
- **식** — FCF = 매출 × 영업이익률 × (1−세율) − Δ매출 ÷ 매출/자본. 잔존 재투자율 g/ROIC(한계 ROIC = 마진 × (1−t) × 매출/자본, 할인율 쪽 절반 수렴)와 같은 식이라 이음새가 없다. 마진 이력은 영업이익률.
- **시나리오** — 보수: 최근 1년 한계 효율과 평균 중 나쁜 쪽 유지 · 기본: 한계 → 평균으로 5년 회복 · 낙관: 평균. 한계 효율 = 1년간 매출 증가 ÷ (설비투자 − 감가상각 + 운전자본 증가 + 인수)(현금흐름 기준, 대차대조표 기준은 지분 평가이익·태그 공백에 흔들려 버림). 비교 시점은 **같은 분기의 1년 전 분기 공시일**(날짜 − 365일은 공시일이 하루만 어긋나도 한 분기 밀림).
- **요구 성장 → 요구 마진** — 요구 성장률이 최근 5년 실제의 3배를 넘거나 해가 없으면 `reqMode: "margin"`, 헤더·내재가치 탭·밸류에이션 위험 문장이 요구 영업이익률을 보인다(AAPL 83.4%, AMZN 28.2%).
- **비영업 자산 분리 표기** — 내재가치 탭에 "기본 $X = 사업 가치 $A + 비영업 자산 $B(주당)".
- **도구** — `v2/build_dcf_block.py {T}`가 `{T}_DCF` 블록을 통째로 만든다(손으로 옮기지 말 것 — AMZN baseEquivGrowth가 다른 입력의 값으로 남아 있던 사례). 순서: `build_dcf_block.py` → `build_dcf_grid.py` → `build_dcf_track.py --json` + 트랙 splice → 산문(시나리오 설명·위험 문장) → `sync_fallbacks.py`. margin 모드 카드의 `.reverse` 대체값은 sync가 못 맞추므로 렌더 문장을 그대로 넣는다.
- 결과(보수/기본/낙관): NVDA 157/314/596 · AAPL 119/130/139 · GOOGL 136/166/176 · MSFT 199/245/265 · AMZN 53/88/99. 할인율 10%·예측 5년(②)은 그대로 — 백로그 70종목 비교에서 다룬다.

- **왜** — SEC companyfacts에 TSM 분기 XBRL이 없고 FY2025 20-F도 2건뿐이다. 대신 매 분기 6-K에 감사인 검토 연결재무제표(HTML, 대만 IFRS, 천 대만달러)가 붙는다.
- **구조** — `v2/adapters/tsm_reports.py`(표 파싱) → `tsm_extract.py`(항목 매핑, 누락 검사) → `tsm_ifrs.py`(분기 도출·companyfacts 모양 → `.sec_cache/0001046179_facts.json`, `--refresh`로 새 6-K 추가) → `tsm_feed.py eps|financials`(SEC를 직접 부르는 두 스크립트에 먹임). 보고서 목록은 `tsm_manifest.json`(28건, 2019 Q3~2026 Q2), 원본 캐시는 `.sec_cache/tsm_reports/`.
- **통화(사용자 결정, Fable 지적 반영)** — 재무는 **대만달러 그대로**, 가격과 만나는 곳만 `v2/fx.py`가 그날 환율(연준 H.10, FRED DEXTAUS)로 바꾼다: 배수 = ADR 가격 × 그날 환율 ÷ 대만달러 재무, 주당 내재가치·순현금은 ÷ 환율로 달러 표시. 분기 평균 환율로 미리 달러 환산하던 첫 방식은 가격의 매일 환율과 섞여 PER·PBR을 최대 10% 흔들었다. 어댑터 파일의 단위 키는 "USD"지만 값은 대만달러(`_adapter.valuesCurrency`). 주식 수·EPS는 ADR 1주(=보통주 5주). 남는 차이는 ADR 프리미엄 — 배수가 대만 본주 기준보다 높고, 자기 이력 백분위에 프리미엄 변동이 섞인다.
- **대조** — 회사 발표와 일치: Q2 2026 달러 매출 $40.20B·EPS/ADR $4.31(분기 평균 환율 환산 시), 총자산 NT$9,375.65B, Q2 설비투자 NT$496.0B·영업현금흐름 NT$783.4B. TTM EPS/ADR $13.56 vs StockAnalysis $13.44.
- **Codex가 잡은 것** — 유동성 장기부채 라벨(새 서식 "Long-term liabilities - current portion") 누락으로 차입금 NT$1,674억 과소, 2019 상반기 덩어리 해의 EPS가 TTM을 엉뚱한 분기로 묶음, fetch_financials가 0짜리 ShortTermBorrowings에서 멈춤(→ DebtCurrent로 싣기), build_dcf CLI 통화 혼용.
- **트랙 주의** — TSM은 주당 가치를 시점 환율로 되돌리므로 트랙 마지막 점(공시일 환율)과 카드 블록(카드 기준일 환율)이 조금 다르다(정상).
- 새 분기: `python3 v2/adapters/tsm_ifrs.py --refresh` → `tsm_feed.py eps` → `tsm_feed.py financials` → 이하 새 카드 절차 3단계와 같다.
