# 주가가 바뀌면 카드에서 무엇이 따라 바뀌는가 (v2)

2026-09-22, NVDA v2 카드를 2026-09-18 종가 $222.27에서 2026-09-21 종가 $227.38로
손으로 옮기면서 만든 지도다. 52군데를 고쳤다. 다음에 이걸 자동화할 때 무엇을
건드려야 하고 무엇을 건드리면 안 되는지 여기 적어둔다.

핵심은 목록이 아니라 **분류**다. 주가에 걸린 값과 안 걸린 값을 먼저 갈라야
"분기 보고서가 나와야 바뀌는 것"을 매일 덮어쓰는 사고가 안 난다.

---

## A. 주가에 걸리지 않는 것 — 매일 갱신에서 건드리지 말 것

분기 공시가 새로 나올 때만 바뀐다. 매일 돌리는 작업이 이것들을 다시 계산하면,
같은 입력으로 같은 답을 다시 쓰거나(무해) 잡음을 섞는다(유해).

| 값 | 근거 | 언제 바뀌나 |
|---|---|---|
| 내재가치 3시나리오 `$159.77 / $315.00 / $602.30` | `build_dcf.scenarios(base_inputs, history)` | 새 10-Q/10-K |
| 적정주가 밴드 `$260~$315` | `PER 33~40x × TTM EPS $7.91` (앵커는 손으로 잡음) | EPS 갱신 시 |
| 기본 시나리오 5년 CAGR `33.9%` | `growth_5y 69.4%`에서 2.5%까지 선형 감쇠한 경로의 기하평균 | 새 공시 |
| 과거 매출 성장률 `3년 +110.6% · 5년 +69.4%` | `history()['growth_3y'/'growth_5y']` | 새 공시 |
| 배수 분모 `EPS 7.91 · BPS 9.43 · 주당매출 12.48 · FCF/주 5.23 · EBITDA 201.3B` | TTM 재무제표 | 새 공시 |
| 예상밴드 체크포인트의 `predicted_low/high` | `compute_earnings_backtest_band.py` | 새 공시 |
| 5단계 앵커 `저/적정/고` | 피어 중앙값, 손으로 잡음 | 재검증할 때 |

**내재가치가 주가와 무관하다는 것은 매번 확인할 수 있다.**

```python
d.base_inputs('NVDA') == d.base_inputs('NVDA', asof='<직전 분기 공시일>')
```

같으면 시나리오 세 값은 그대로다. 2026-09-22 확인 결과 같았고, 시나리오도
$159.77 / $315.00 / $602.30로 동일했다.

## B. 주가에 걸리는 것

### B1. 순수 공식 — 분모만 있으면 자동

분모는 A에 있고 매일 바뀌지 않으므로, 새 종가 `P` 하나로 전부 다시 쓸 수 있다.

```
PER        = P / EPS
PBR        = P / BPS
PSR        = P / 주당매출
PCR        = P / (FCF/주)
EV/EBITDA  = (P × 주식수 + 차입금+리스 − 현금+단기투자) / EBITDA

게이지 폭   = (값 − 저) / (고 − 저) × 100          ← val-fill의 width
밴드 마커   = (P − Bear하단) / (Bull상단 − Bear하단) × 100
목표가 여력 = 목표주가 / P − 1
52주 대비   = P / 52주저점 − 1,  P / 52주고점 − 1
1년 수익률  = P / 253거래일전 종가 − 1
```

NVDA의 밴드 축은 Bear $160 ~ Bull $515다. 목표가 마커 46.8%가 이 축에서
정확히 재현되므로 축 가정이 맞다는 검산이 된다.

### B2. 스크립트를 다시 돌려야 하는 것 — 공식이 없다

**현재가 요구 성장률**은 이분법으로 찾는다. 닫힌 식이 없으므로 비율로 근사하면 안 된다.

```python
mp  = d.margin_path_for(hist, '기본')          # 헤더 내재가치와 같은 시나리오
req = d.implied_growth(base, P, wacc=0.10, terminal=0.025, margin_path=mp)
```

카드에는 세 시나리오가 다 실린다(내재가치 탭의 표). 셋 다 다시 계산한다.

| P | 낙관(마진 66.4%) | 기본(62.8%) | 보수(56.6%) |
|---|---|---|---|
| $222.27 | 23.95% | 25.43% | 28.16% |
| $227.38 | 24.58% | 26.06% | 28.81% |

**헤더에 싣는 값은 반드시 `기본`이다.** 옆 칸의 내재가치 $315가 기본 시나리오라
전제를 맞춰야 한다. 마진 가정만 바꿔도 답이 4%p 넘게 갈린다.

### B3. JS가 알아서 하는 것 — 배열만 갈아끼우면 된다

`NVDA_DAILY` / `MA5` / `MA20` / `MA60` / `MA120` 다섯 배열을 교체하면 페이지
로드 시 자동으로 맞는다. 정적 HTML 텍스트는 같은 값을 쓰는 **대체물**일 뿐이다.

- 밴드 적중률(헤더 4번 칸), 그 라벨과 툴팁
- 박스별 적중률과 색, 박스 툴팁
- 차트 제목의 1년 수익률, `techRangeSummary`
- 열린 예상밴드 구간의 오른쪽 끝(마지막 일봉까지 자동으로 늘어난다)

정적 텍스트를 고치지 않아도 화면은 맞다. 다만 JS가 죽으면 옛 숫자가 드러나므로
같이 맞춰두는 편이 낫다.

### B4. 산문에 박혀 있는 것 — 자동화의 진짜 난관

값이 문장 안에 녹아 있어서 문자열 치환만으로는 부족하다. 2026-09-21 갱신에서
실제로 고친 것들이다.

| 문장 | 규칙 |
|---|---|
| `"이 회사가 5년간 연 26%씩 클 수 있나?"` | 요구 성장률을 **정수로** 반올림 |
| `26.1 ÷ 33.9 = 0.77` | 요구 성장률 ÷ 기본 CAGR, 소수 둘째까지 |
| `이 질문의 답도 24.6~28.8%로 움직인다` | 세 시나리오의 최소~최대 |
| `NVDA 28.7x는 자체 10년 기준점 53x보다 낮음` | 배수값만 치환 |
| `2026.09.21 종가 $227.38은 ... +43.4% 여력이 있다` | 날짜·가격·여력 세 곳 |
| `52주 저점 대비 +38.42%, 고점 대비 -3.87%` | 소수 둘째까지 |

**비교 서술이 뒤집히는 경우가 제일 위험하다.** 이번에 PBR이 `23.5x → 24.1x`가
되면서 앵커 `AVGO 24.0x`를 넘었다. 판정 문장이 "AVGO 24.0x와 거의 근접"이었는데
이제 웃돈다. 값만 바꾸면 문장이 거짓이 된다.

자동화한다면 **부등호가 뒤집히는 순간을 검출해 사람에게 넘기는** 장치가 필요하다.
치환 대상마다 "이 문장이 주장하는 부등식"을 같이 적어두는 방식이 맞다.

## C. 이미 있는 인프라 — 다시 만들지 말 것

`site_data/valuation_base/{TICKER}.json`이 stage 2B용으로 이미 존재하고,
`pipeline/update_cards.py`가 매일 이것으로 **루트 카드의** 밸류에이션 탭을 갱신한다.

```json
{ "p0": 228.45, "cardAsOf": "2026-09-03",
  "metrics": [ { "metric": "per", "value0": "28.9", "width0": "16.3",
                 "low": "15", "high": "100", "method": "price-ratio",
                 "badge": "1단계 매우낮음", "frozen": false }, ... ],
  "targetBand": { "ranges": [["160","215"],["260","315"],["395","515"]],
                  "marker0": "19.3", "target": "325.99", "upside0": "+42.7" } }
```

- `method: "price-ratio"` — 값 = `value0 × P / p0`
- `method: "ev-delta"` — `EV = ev0 + (mcap0 × P/p0 − mcap0)`
- `frozen` — true면 그 배수는 갱신에서 뺀다

v2에 필요한 것은 이 구조의 **확장**이지 대체가 아니다. 다만 아래 두 가지가 빠져 있다.

1. **요구 성장률과 내재가치 탭**을 모르는다. B2는 새로 붙여야 한다.
2. **`price-ratio`가 이중 반올림을 한다.** 아래 참조.

### ⚠ 라이브 버그 — `price-ratio`의 이중 반올림

`value0`은 이미 소수 첫째까지 반올림된 값이다. 거기에 비율을 곱하면 원본에서
직접 계산한 값과 한 틱 어긋날 수 있다.

```
루트 카드 (2026-09-21, 파이프라인 산출)
  calcLine: 'PER = 주가($227.38) ÷ EPS($7.91) = 28.8x'
  실제로 나누면            227.38 / 7.91 = 28.7459  →  28.7

  경로: value0 28.9(참값 28.88) × 227.38/228.45 = 28.765 → 28.8
```

카드가 자기 계산식과 어긋나는 값을 표기한다. PBR·PSR·PCR·EV/EBITDA는 이번
가격에서 우연히 일치했지만 같은 구조라 언제든 어긋난다.

**고치는 법은 분모에서 직접 재계산하는 것이다.** 분모(EPS/BPS/주당매출/FCF주당)를
baseline에 넣어두면 `price-ratio`를 쓸 이유가 없어진다. 2026-09-22 현재
v2 카드는 분모 직접 계산(PER 28.7x), 루트 카드는 비율(28.8x)이라 둘이 다르다.

## D. `update_cards.py`를 v2에 그대로 쓸 수 없는 이유

`--cards-dir v2`로 가리킬 수는 있으나 아래에서 멈춘다. 모든 치환이 **정확히 한 번**
맞아야 하고 안 맞으면 카드를 안 쓰고 넘어간다.

| 앵커 | 루트 | v2 | 결과 |
|---|---|---|---|
| `<div class="price-main">$227.38</div>` | 그대로 | 안에 `<span class="price-change">`가 들어 있다 | 불일치 |
| `<div class="price-change" ...>▲ +2.30% (2026.09.21 기준)</div>` | div, 날짜 포함 | **span**, 날짜 없음 | 불일치 |
| 헤더 `52주 최저 … · 최고 …` 줄 | 있음 | **없음** | `EditError` (하드 실패) |
| `meta-label">시가총액</span>` | 있음 | **없음** | 주식수가 있으면 실패 |
| `id="techHeaderTitle">기술적 분석 — 일봉 캔들스틱 (` | 그대로 | `주가 차트 — 일봉 캔들스틱 (` | 불일치 |
| `id="techRangeSummary">` | 그대로 | 형식까지 동일 | **통과** |
| `const NVDA_DAILY = [...];` 한 줄 | 그대로 | 그대로 | **통과** |
| `<div class="scorecard-score">` | 있음 | 있음(86.3) | 통과하나 **이 블록은 정리 예정** |

v2 헤더는 네 칸(적정주가·내재가치·요구성장·밴드적중률)뿐이고 52주·시가총액 칸이
없다. 루트의 헤더 규칙을 그대로 쓸 수 없다는 뜻이다.

## E. 함정

**세대가 섞인다.** 고치기 전 v2 카드에는 주가가 세 세대 있었다.

```
09-03 $228.45  투자판단 탭  PER 28.9x·PBR 24.2x·PSR 18.3x·PCR 43.7x·EV/EBITDA 27.2x
09-18 $222.27  밸류에이션 탭 PER 28.1x·PBR 23.5x·PSR 17.8x·PCR 42.5x·EV/EBITDA 26.5x
그 이전        86.3 스코어카드 PER 44.55x·PBR 33.72x·애널리스트 57명
```

한 번에 전부 안 고치면 세대가 늘어난다. **치환 목록은 탭 단위가 아니라 값 단위로
관리해야 한다.**

**루트 카드가 이미 최신이면 네트워크가 필요 없다.** 매일 파이프라인이 루트를
갱신하므로 다섯 배열을 그대로 복사하면 된다. 2026-09-21 갱신은 이렇게 했다.
정렬 확인은 `root[j] == v2[j+1]` 가설을 전 구간에서 검증하는 식으로 한다
(이번엔 09-18 거래량 한 건만 달랐고, 그건 파이프라인의 정정이라 루트가 맞다).

**배열은 절대 손으로 옮겨 적지 않는다.** 스크립트로 원본에서 잘라 붙인다.

**단계 배지는 앵커를 교차할 때만 바뀐다.** 값이 움직여도 `저/적정/고`를 안 넘으면
등급은 그대로다. 2026-09-21에는 다섯 배수 모두 교차하지 않았다. 교차 검사를 빼면
값과 배지가 어긋난다.
